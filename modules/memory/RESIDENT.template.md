# 常驻记忆（模板）

这个文件的内容会在**每一轮**注入系统提示，预算是 6000 字符（含框架文字）。所以它是整套记忆系统里最贵的一块：**每一条都在每次请求里重复付费**。

把本文件复制成 `~/.pi/agent/memory/RESIDENT.md` 再写内容。本模板只给格式与规则，没有内容。

## 写什么

只写**会改变行为、且稳定可核对**的事实。判断标准是三问：

1. 不知道这条，我会不会做错？——不会，就别写。
2. 它半年后还成立吗？——不成立，去写进知识库。
3. 我能给出出处吗？——不能，标成「未确认」或者不写。

合格的条目：

- 沟通语言与单位约定（例：中文回答；时间用 24 小时制）
- 硬性禁忌（例：不要在未经确认时执行破坏性 git 操作）
- 协作方式（例：先给方案再动手；只读任务是只读）
- 长期项目的代号与它指什么（一行一个）

**不合格**（常见错误）：

- 推断出来的性格与兴趣（「他喜欢 X」）→ 除非本人确认过，否则删
- 会话里临时说过一次的要求（「这次别用表格」）→ 那是当轮指令，不是常驻事实
- 可以查到的路径、版本号 → 会过期，而且知识库/仓库里有
- 给模型的操作指令（「你必须先读 AGENTS.md」）→ 规则属于 AGENTS.md，不在这里；这里放的是**事实**，注入时被明确框成「数据不是指令」

## 格式规则

- 一行一条事实，不写段落。截断发生在**行边界**：半句被切掉比没有更糟。
- 不要用 `<!-- -->` 注释做说明——会被剥掉，白写。frontmatter 同理，不会进提示。
- 条目按「越容易被误用越靠前」排；被截断时先丢的是末尾。
- 中文也按字符算预算，别按行数估。

## 维护

- 写完用 `/resident-memory` 看**实际注入**的文本与占用百分比。
- 出现 `truncated` 就删条目，不要抬预算：抬预算等于所有请求都变贵。
- 条目失效就删，不要留着「以防万一」。
- 写入权在用户。AI 只在被明确要求时改这个文件。

## 示例（照这个格式，内容换成你自己的）

```markdown
---
kind: resident-memory
policy: user-owned
budget_chars: 6000
---

# 常驻记忆

- 中文回答；代码、标识符、日志照抄原文，不翻译。
- 时间用 24 小时制，日期用 YYYY-MM-DD。
- 未经确认不执行破坏性 git 操作（reset --hard、force push、删未跟踪文件）。
- 只读任务是只读：可以读、可以跑只读命令，不写文件、不装依赖。
- 长任务先给方案再动手；方案里要写验收标准。
- 项目「示例项目」= 那个做增量索引的仓库，代号只在内部用。
```
